# Design Records

`design/` holds durable records for meaningful system and operational changes.
Create one dated document per decision, named
`YYYY-MM-DD-<topic>-design.md`.

Each design record MUST use this template:

```markdown
# <Title>

## Context

## Constraints

## Decision

## Alternatives

## Assumptions

## Operational Impact

## Ownership

## Risk and Failure Modes

## Rollout

## Rollback

## Verification
```

State operational impact and ownership where they affect the decision. English
is authoritative; add Chinese annotations for critical operational requirements
when they improve clarity.
